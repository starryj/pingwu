# M9 物品通用化

> 目标：把「只能记药」改成「能记任何东西」；提醒从「只能每天」改成四种规则；补上物品的修改与删除。
> 版本：`0.9.0-m9`（versionCode 12）

## 一、为什么改

作者在 真机 上实测后指出三件事：

1. 添加接口还是药品专用（剂量 / 每次几片 / 白色药片 / 蓝色胶囊），而凭物的目标是钥匙、钱包、护照、纸巾这类身边的东西；
2. 提醒只能选「每天」，希望能选「每周三」「11 月 15 日上午 9 点」这种；
3. 物品没有修改和删除功能，进到详情页也没有。

确认过的四个决定：

| 问题 | 决定 |
|---|---|
| 字段怎么改 | 名称 + 备注（可空）+ 每次几件 + 封面照，**再加分类图标**（钥匙 / 证件 / 药品 / 其他） |
| 提醒规则 | 每天 / 每周选星期几 / 每月某日 / 一次性某天某时，四种都要 |
| 旧数据 | 清空重来（旧的 3 个物品与凭物一起清掉，不再保留种子数据） |
| 删除语义 | 物品归档，凭物记录保留 |

## 二、数据层

- 新 `data/core/ReminderRule.kt`：`DAILY / WEEKLY / MONTHLY / ONCE` 四种规则的解析、摘要文案（`每天 08:00 · 21:00`、`每周一、三 08:00`、`每月 3 日 08:00`、`11.14 周六 08:00`）与下一次触发时刻计算；`ReminderEntity` 新增 `rule / daysCsv / onceDate`。
- `ItemEntity`：`dose` + `kind` 换成 `note`（备注）+ `category`（药品 / 钥匙 / 证件 / 其他）。
- 数据库 `version = 2` + `fallbackToDestructiveMigration(dropAllTables = true)`：按「清空重来」直接重建，不写迁移。
- `PingWuRepository`：删掉 `seed()`（不再有内置药品与假历史）；新增 `addItem(ItemDraft)` / `updateItem(id, draft)` / `archiveItem(id)`；今日待办按规则生成（不是每天都铺）；`nextScheduledAfter` 与新增的 `buildNextUp` 都走 `ReminderRule.nextAfter`，所以「每周三」的物品今天没安排时，首页显示的是「下一次 08:00 · 11.18 周三」。
- `Mapper`：`toUiItem` 的 schedule 直接取 `ReminderRule.summaryOf`；`drawableFor` 未知 key 返回 0（不再有药片兜底图）。

## 三、界面

- **添加 / 编辑物品**：同一个页面，`AddItemScreen(editing = ...)`。名称、备注（可空）、每次几件（− N ＋，并提示「拍照时要看到 N 件」）、分类四宫格；提醒区四个 chip（每天 / 每周 / 每月 / 一次），选「每周」出现七个星期 chip，选「每月」出现号数加减，选「一次」出现日期选择器；时间可加多个、点「改」开时间选择器；验证窗口 15 / 30 / 60 分。右上角实时预览规则摘要（如「每周三 08:00」）。
- **物品列表**：卡片图标按分类画（药片 / 钥匙 / 证件 / 其他），副行是「备注 · ×数量」，下面是规则摘要；列表为空时显示「还没有物品 + 添加第一件物品」。
- **物品详情**：右上「编辑」；头部 `×1 · 钥匙` + 规则摘要；下方红字「删除这件物品 / 已有的凭物会保留」，点击弹确认（「删掉「X」？…先留着 / 删掉」）；没有历史时统计显示「—」而不是 100%。
- **今日**：没有物品时整页是「第一次用」空态卡（不再显示空的进度和周条）；「下一次」卡在「今天没有安排」时显示规则算出来的下一次并标「排着」；周条改成三态（按时 / 漏拍 / 无安排），没有安排时不显示百分比。
- **去药品化文案**：全屏提醒兜底名「白色药片」→「那件东西」、「到吃药时间了」→「到点该拍了」；拍照页提示「倒出来、分开摆、全部在画面里」→「摆好、看清楚、全部在画面里」；CSV 表头「剂量」→「备注」、「应服」→「应拍数」。

## 五、已知边界

- 一次性规则拍完就结束：日期过去后不会再生成待办（也不自动删除物品）。
- 分类图标只有四种，先覆盖常见场景；以后要加，改 `ItemCategory` 与 `ItemGlyph` 两处即可。
- 旧库按「清空重来」处理——升级会丢掉 M8 及以前的物品与凭物，这是作者确认过的取舍。
