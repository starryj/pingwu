# M10 到点页与验证页修正

> 起因：作者 2026-11-13 真机实测反馈两条。
> 版本：0.10.0-m10（versionCode 13）

## 一、作者反馈的两条

1. **到点之后没有全屏显示**；点开通知进入拍照验证界面后，这个界面能退出——没有达到「没验证不能走，只能紧急/推迟」的约定。
2. **拍照验证页里出现的是之前的图（内置示例图），不是我拍的「坚果」模板照。**

## 二、第一条：全屏与不可退出

### 系统限制（要说清楚）

Android 14 起，**全屏 Intent 只在锁屏/熄屏时有效**。手机解锁着、App 不在前台时，系统只允许发一条横幅通知，任何应用都抢不了全屏（除非走设备管理/无障碍这类特殊权限，凭物不做）。

所以能保证的是两件事：

- **锁屏时**：全屏验证页照旧弹出（`setShowWhenLocked` + `setTurnScreenOn` + full-screen intent）。需要在系统里给到：通知权限、精确闹钟、全屏通知、HyperOS 的「锁屏显示」与「后台弹出界面」。这些在「我的 → 到点提醒」里有入口与状态。
- **应用在前台时**：由 App 自己弹同一个到点全屏页（不再依赖系统）。

### 应用内到点页（新增 `ui/screens/AlarmScreen.kt`）

- 由 `PingWuViewModel.dueTask` 驱动：`PingWuRoot` 里每 15 秒 `refreshDue()`，取今天已到点、还没拍的最近一条。
- 内容与锁屏页一致：时间、「到点该拍了」、`拍一张 X ×N，才算这次完成。`、物品自己的模板照、`拍照只是在场证明：证明东西在，不证明已经做了。`
- 两个出口：**稍后 10 分钟** / **去拍照**。
- 左上角 `物品名 ×N` 小标签；并拦截返回键——按返回弹「还没拍呢 / 现在走的话，会记一次推迟，10 分钟后再提醒你」，只有「推迟」能离开。

### 拍照验证页也不许随手退出

`ui/screens/CapturePlaceholderScreen.kt`：

- 判定 `blocking = pending != null && templateItemId == null`（到点验证才算，登记模板照是自由操作）。
- `BackHandler(enabled = blocking)` → 弹「还没拍完 / 这一条还没验证。先走的话会记一次推迟，10 分钟后再提醒你」，「继续拍」留着，「推迟」才走。
- 顶部返回箭头走同一逻辑。

### 推迟要真的算数

`reminder/ReminderScheduler.kt` 的 `snooze(context, minutes = 10)` 重排一次闹钟；同时 `PingWuRepository.snoozeOccurrence(id, untilMs)` 把这一条 `scheduledAt` 往后挪并写进数据库（`OccurrenceDao.reschedule`）。
这样即使杀掉进程、重启手机，也还是「10 分钟后再提醒」，不会一打开 App 又立刻弹回来。

## 三、第二条：到点页显示的是物品自己的模板照

原因：`ReminderActivity` 里那张图是硬编码的 `R.drawable.pw_photo_2`（内置的 4 颗白药片示例图），跟物品自己的封面照没有关系。

改法：

- `PendingTask` 带上 `coverPhotoKey`（物品自己的模板照路径）；`ReminderNotifier.notify(...)` 与 `ReminderReceiver` 把它传给 `ReminderActivity`（`EXTRA_COVER`）。
- 到点页（锁屏版与应用内版）都用 `PhotoImage(coverPhotoKey)` 显示**它自己的**样子。
- 还没登记过模板照时，不再拿别人的图凑数，显示占位：「还没给它拍样子 / 去「物品」里补一张，下次提醒就显示它」。

## 四、顺手修掉的统计口径

- 刚装好、只有今天一条还没拍时，「近 7 天」右侧显示 `100%` 但标题是「0 天按时」，自相矛盾。现在没有任何「有结果」的记录时显示 `—`（新增 `EvidenceStats.decidedCount`）。
- 周条最后一格：今天是「排着、还没拍」时，原本按「按时」亮满；现在用不同的高度与透明度区分，下面标「待」，不再是假的「按时」。

## 六、已知边界

- 解锁状态、App 在后台：只能有一条通知横幅，点它才进拍照页。这是系统行为，不是 App 能改的。
- 应用内到点页靠 15 秒轮询，最坏情况会晚十几秒出现；而系统闹钟/通知那一层是准点触发的。
- 推迟写库会改这一条的 `scheduledAt`，但 `timeLabel`（16:00 这种）保持不变，凭物上记的仍是原来那一次。

## 0.10.1：锁屏不亮屏的根因 + 上滑回桌面

### 1. 锁屏黑屏时屏幕不亮

实机取证（真机，0.10.0-m10）：把一条提醒设到 16:46，熄屏等待。到 16:46 时设备仍是
`mWakefulness=Dozing`，没有通知、没有 `PwReminder` 日志；到 **16:48:19** 才出现
`whetstone.activity ... type=RTC_WAKEUP statsTag=*walarm*:com.pingwu.app/.reminder.ReminderReceiver`
和 `START ... ReminderActivity`，同时屏幕被点亮。

结论：不是全屏 Intent 失效，而是**精确闹钟在息屏 / Doze 下被系统推迟了约 2 分 19 秒**。
投递之后全屏页、通知、点亮屏幕都正常。

改法（`reminder/ReminderScheduler.kt`）：把 `setExactAndAllowWhileIdle` 换成
`AlarmManager.setAlarmClock(AlarmClockInfo(at, showIntent), pending)`：

- 系统把它当真正的闹钟，息屏也会准时唤醒设备，状态栏会出现闹钟图标；
- 没有「精确闹钟」权限时退回 `setAndAllowWhileIdle`，至少不会完全不响；
- 推迟（10 分钟）也走同一套。

验证（模拟器，1080×2400）：把提醒设到 3 分钟后 → 熄屏（`mWakefulness=Asleep`）→
到点 **准点** `START ReminderActivity`、`mWakefulness=Awake`，到点页正常弹出
（截图 `docs/shots/m10-alarmclock-wake.png`）。

小米 / 红米的经验：如果仍会晚几分钟，多半是系统在管后台。已在我的 →「到点提醒」卡里
加了两个入口 —— **自启动**（`miui.intent.action.OP_AUTO_START`）和 **省电策略**
（powerkeeper 的 HiddenAppsConfig），把凭物设成「允许」「无限制」即可。
截图：`docs/shots/m10-miui-buttons.png`。

### 2. 上滑回桌面绕过验证

HOME 手势是系统行为，普通应用拦不住（能拦的只有设备管理员/无障碍/桌面启动器）。
因此改成两层：

- **默认：回来就补弹**。到点未验证时，App 从桌面/别的应用回到前台会立刻重新打开展示
  到点页（`PingWuRoot` 里监听 `ON_RESUME` 调 `refreshDue()`），等于绕不过最后这一下。
- **可选：专注模式（屏幕固定）**。我的 →「设置」里新增开关，打开后到点会
  `startLockTask()` 把提醒页钉在屏幕上，要按住返回 + 多任务才能解，等于明确选择
  「这次不拍」。截图：`docs/shots/m10-focus-lock.png`。
  注意：系统需要允许「屏幕固定」（部分 ROM 在 设置 → 安全 里），否则只会有默认的
  「回来就补弹」这一层。

### 版本与检查

- `versionCode 14` / `versionName 0.10.1-m10`
- `:app:testDebugUnitTest` 26/26；`:app:lintDebug` 0 errors / 27 warnings / 3 hints
- 真机 已装 0.10.1-m10

### 已知边界

- 普通应用无法真正禁止「回桌面」，只有「回来必须面对」。
- 屏幕固定需要系统开关；关了就只有第一层。
- 部分 ROM 的省电策略仍可能让闹钟晚到，需要在系统里把凭物设为不限制。

## 0.10.2：到点不响的三层原因与修法

作者在 0.10.1 上复验：熄屏时到点没有亮屏、没有铃声也没有振动；桌面上滑清理 App 后完全收不到提醒。逐层查下来是三个独立问题。

### 一、没有铃声和振动：渠道建错了

旧通知渠道 `pw_reminder` 建立时没有指定铃声与振动，NotificationRecord 里 `sound=null vibrate=null`。Android 的渠道属性在创建后不可修改，所以只能换 id 重建：

- 新渠道 `pw_reminder_v2`：`setSound(系统闹钟铃声, AudioAttributes(USAGE_ALARM))`、`vibrationPattern = [0, 500, 240, 500, 240, 800]`、`lockscreenVisibility = PUBLIC`、importance 高。
- `ReminderNotifier.notify()` 与 `notifySelfTest()` 里都显式调用振动器（`VibrationEffect.createWaveform(VIBRATION, -1)`），不依赖渠道是否被用户关掉振动。

### 二、熄屏时不醒：闹钟要按「闹钟」排

原实现用 `setExactAndAllowWhileIdle`。实机取证（16:46 的提醒 16:48:19 才到）说明 Doze 下它会晚到两分多钟。0.10.1 已改成 `AlarmManager.setAlarmClock()`（系统按闹钟对待，Doze 也放行、状态栏出现小闹钟图标），0.10.2 再补上 `USE_EXACT_ALARM` 权限声明，让 `canScheduleExactAlarms()` 在更多机型上直接为真。

### 三、清理 App 后不响：那是强制停止

在最近任务里「清理」等于 `force-stop`，系统会把这个包的闹钟一起取消 —— 这不是代码能绕过的。应对放在两处：

- 「到点提醒」卡里给小米/红米加「自启动」「省电策略」入口，说明要允许自启动、省电设为「无限制」。
- 卡里加一句：想让它常驻，可以在最近任务里长按凭物 → 上锁（锁定后清理不会杀掉）。

### 新增：让用户自己能确认「到底响没响」

- **到点自检（1 分钟）**：只排一次 1 分钟后的测试闹钟，不影响真实提醒；响完在卡片里写结果。
- **最近一次提醒**：记录每次真实提醒的计划时间与实际触发时间，显示「17:48 准点」或「晚了 N 分」，一眼看出被系统压了多久。

### 验证

- 真机（HyperOS 3 / Android 16）：把「香水」提醒改到 17:48，`dumpsys alarm` 确认是 `Alarm clock:` 类型；`keyevent 26` 熄屏后 `mWakefulness=Dozing`；到 17:48:00 准时 `mWakefulness=Awake`、`mCurrentFocus=com.pingwu.app/.reminder.ReminderActivity`，通知记录 `channel=pw_reminder_v2`、`mSound=content://settings/system/alarm_alert`、`mVibrationPattern=[0,500,240,500,240,800]`。截图 `docs/shots/m10-2-alarm-wake.png`。
- 同一轮还拍下 `m10-2-alarm-page.png`（到点页显示「香水」自己的模板照）与 `m10-2-reminder-card.png`（卡片显示「最近一次提醒 17:48 准点」）。
- 构建：`:app:assembleDebug :app:testDebugUnitTest :app:lintDebug` 全部通过，单测 26/26，Lint 0 error。
- 版本：`versionCode 15` / `versionName 0.10.2-m10`。

### 已知边界

- 一次性提醒（ONCE）过去之后不会再有下一次，这是规则本身如此；要长期提醒请用「每天 / 每周 / 每月」。
- 各 ROM 的「清理」行为不同：强制停止一定取消闹钟；上锁后通常不会。

## 0.10.3：为什么屏幕亮了却没有声音

作者在 0.10.2 上复验：准点亮屏了，但没有铃声也没有振动。模拟器复现后抓到真正的原因——

```
D PwAlarm : start reason=activity
W PwAlarm : sound failed: SecurityException Neither user 10235 nor current process has
            android.permission.WAKE_LOCK.
D PwAlarm : vibrate start
```

`MediaPlayer.setWakeMode()` 需要 `WAKE_LOCK` 权限，而清单里没有声明；异常被 runCatching 兜住、只写了一条日志，于是**播放器根本没起来**，屏幕照样亮（全屏 Intent 与播放器无关），所以看起来是「亮了但没声」。

### 改法

- 新建 `reminder/AlarmPlayer.kt`：到点时自己播铃 + 振动，不再把「响」交给通知渠道。
  - 声音：`MediaPlayer` + `USAGE_ALARM`，循环播放系统闹钟铃声，`setWakeMode(PARTIAL_WAKE_LOCK)` 保证后台继续响，并申请 `AUDIOFOCUS_GAIN_TRANSIENT`。
  - 振动：`VibrationEffect.createWaveform([0,600,300,600,300,900], 0)` 无限循环（这是「响到有人管」的关键，通知渠道的振动容易被 ROM 吞掉）。
  - 音量兜底：闹钟音量为 0 时抬到最大的一半并记日志，否则等于没设闹钟。
  - 5 分钟自动停：没人理会就不再制造噪音。
- 清单补 `<uses-permission android:name="android.permission.WAKE_LOCK" />`。
- `ReminderActivity` 创建时 `AlarmPlayer.start()`、销毁时 `stop()`；应用内到点页（`PingWuRoot`）同样按 `dueTask` 起停，点「稍后 / 去拍照」立刻停。

### 验证（模拟器 emulator-5554，Android 16）

1. 我的 → 到点提醒 → 到点自检（1 分钟）→ `keyevent 26` 熄屏，`mWakefulness=Asleep`。
2. 1 分钟后：`mWakefulness=Awake`、`mCurrentFocus=com.pingwu.app/.reminder.ReminderActivity`。
3. 日志：`PwAlarm: sound start uri=content://settings/system/alarm_alert alarmVolume=6/7`、`vibrate start`。
4. `dumpsys audio` 里出现本进程的播放器：`type:android.media.MediaPlayer u/pid:10235 state:started attr:usage=USAGE_ALARM`，且音频焦点 `GAIN_TRANSIENT` 已拿到。
5. 点「稍后 10 分钟」→ 日志 `PwAlarm: stopped`、回到主界面。

截图：`docs/shots/m10-3-alarm-ring.png`。

### 版本

`versionCode 16` / `versionName 0.10.3-m10`；单测 26/26、Lint 0 error。

### 已知边界

- 静音 / 勿扰下 `USAGE_ALARM` 仍会响（除非用户关掉「闹钟响铃」）；但若用户把闹钟音量调到 0，App 只会抬到一半，不做无上限拉满。
- 通知渠道仍保留声音与振动：全屏 Intent 被系统拒绝时，它还是兜底的那一层；两者同时响时，开头会叠一下。
