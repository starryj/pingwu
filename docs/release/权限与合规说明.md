# 凭物 · 权限与合规说明

对应版本：0.6.0-m6（versionCode 6）
用途：提交商店时的权限说明素材，以及自己排查用。

---

## 1. 权限清单（与 AndroidManifest 一致）

| 权限 | 类型 | 用途 | 触发时机 | 拒绝后果 |
|---|---|---|---|---|
| `CAMERA` | 危险权限，运行时申请 | 拍物品照片作为完成凭证 | 第一次进拍照页 | 只能看历史，不能新增凭物 |
| `POST_NOTIFICATIONS` | 危险权限（Android 13+） | 到点提醒 | 首次启动 / 首次排提醒 | 收不到通知；App 内会提示去开 |
| `SCHEDULE_EXACT_ALARM` | 特殊权限（Android 12+） | 准点触发提醒 | 首次排提醒前检查 | 退化为不精确闹钟，可能延迟几分钟 |
| `USE_FULL_SCREEN_INTENT` | 特殊权限（Android 14+） | 锁屏直接亮起验证页 | 发提醒前检查 | 退化为普通高优先级通知 |
| `RECEIVE_BOOT_COMPLETED` | 普通权限 | 开机/改时间后重排提醒 | 系统广播 | 重启后提醒可能不响，需打开 App |
| `INTERNET` | 普通权限 | 在线识别请求 | 用户开启在线识别并拍照 | 在线识别不可用，本机识别照常 |
| `ACCESS_NETWORK_STATE` | 普通权限 | 判断网络是否可用 | 在线识别前 | 在线识别错误提示可能不准确 |
| `VIBRATE` | 普通权限 | 提醒震动 | 发提醒 | 无震动 |

**没有申请**：位置、通讯录、短信、电话、存储读写（用应用私有目录 + FileProvider）、后台定位、读取应用列表。

## 2. 数据流（审核重点）

```
拍照
 ├─ 本机路径：照片 → filesDir/evidence/日期/ → OpenCV DNN 检测 → 判定 → Room 记凭物
 └─ 在线路径（用户开启且填了 Key）：照片 base64 → 用户填的 OpenAI 兼容服务商 → 返回 pass/reason
        （不经过开发者服务器；Key 只存本机 SharedPreferences）
```

- 照片默认保留 180 天，可手动清理
- CSV 导出到 `cacheDir/exports/`，分享后 7 天自动清理
- `allowBackup="false"`：不参与系统云备份

## 3. 商店政策注意点

### 3.1 医疗健康类目（国内商店）

- 用药提醒通常被归到「医疗健康」类目
- 国内商店该类目多要求企业主体 + 相关资质；个人开发者通道基本关闭
- 描述里不要出现「诊断」「治疗」「推荐剂量」；已写「不构成医疗建议」

### 3.2 生成式 AI / 在线识别

- App 不内置 Key、不代用户调用，属于「用户自备 Key 的工具」，不是生成式 AI 服务提供者
- 但部分商店审核仍会问「是否含 AI 生成内容」，需要能说明：只做照片是否通过的判断，不生成内容、不提供医疗建议
- 首次开启在线识别时的提示文案已写「照片会发到你填的服务商」

### 3.3 全屏 Intent（Google Play）

- Play 政策把 `USE_FULL_SCREEN_INTENT` 限定在闹钟、来电等场景
- 本 App 属于「用药提醒」，有合理场景，但审核可能要求说明
- 如果被拒：改成「高优先级通知 + 点击进入全屏页」，代码里 `ReminderNotifier` 已支持 `fullScreen=false` 降级

### 3.4 精确闹钟（Google Play）

- `SCHEDULE_EXACT_ALARM` 需要声明核心功能；用药提醒属于合理用途
- 备选：`USE_EXACT_ALARM`（仅限闹钟/日历类，审核更严），不建议

### 3.5 targetSdk

- 当前 compileSdk 37 / targetSdk 36，满足 2026 年主流商店要求

### 3.6 广告与付费

- 无广告、无内购、无账号，年龄分级可填 3+

## 4. 提交时可能需要回答的问题

- **App 是否收集个人信息？** 不收集；数据只存本机；在线识别是用户可选、发给用户自己配置的服务商。
- **为什么需要相机？** 拍照作为「这件事确实做了」的凭证，是核心功能。
- **为什么需要全屏通知？** 用药提醒需要在锁屏上直接显示验证页，减少漏服。
- **为什么需要精确闹钟？** 用药时间需要尽量准点。
- **是否含医疗建议？** 不含；只做提醒和记录。
- **AI 功能是什么？** 可选的照片通过/不通过判断，用户自备 Key，默认关闭。
