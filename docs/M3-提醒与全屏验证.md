# M3：到点提醒与全屏验证

> 版本 0.3.0-m3（versionCode 3）
> 目标：到点叫得醒、点开就能拍、窗口可以自己定。

## 一、做了什么

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 到点通知 | `reminder/ReminderNotifier.kt` | 高优先级渠道 `pw_reminder`，带全屏 Intent 与「去拍照」动作 |
| 排闹钟 | `reminder/ReminderScheduler.kt` | 只排「下一个」；响过再排下一个；无精确闹钟权限时退到 `setAndAllowWhileIdle` |
| 到点响应 | `reminder/ReminderReceiver.kt` | 补今天待办 → 标漏拍 → 有到点待拍就发通知 → 排下一个 |
| 开机/改时间 | `reminder/BootReceiver.kt` | `BOOT_COMPLETED` / `TIME_SET` / `TIMEZONE_CHANGED` 后重排 |
| 全屏验证页 | `reminder/ReminderActivity.kt` | 锁屏直接亮起；「去拍照」进主界面拍照验证；「稍后」关掉 |
| 可调验证窗口 | 物品详情页 + `Repository.updateWindow` | 15 / 30 / 60 分钟；同时改提醒与今天未完成待办的窗口 |
| 权限可见 | 「我的 → 到点提醒」卡 | 通知权限、精确闹钟状态、一键跳系统设置 |

## 二、关键设计

### 1. 只排一个闹钟

不按条排、不排一周：每次响完（或 App 打开、加物品、开机）调用 `ReminderScheduler.scheduleNext()`，
由 `PingWuRepository.nextScheduledAfter()` 从所有启用的 `timesCsv` 里算出「此刻之后最近的一次」。
好处：不会因为改时间、删物品留下一堆孤儿 alarm；代价：每次响都要能重新排，所以 Receiver 里必须做。

`ScheduleCalculator.nextAfter(times, now, zone)` 是纯函数，单测覆盖了「今天还有一次 / 今天都过了排明天 / 空时刻 / 重复时刻」。

### 2. 全屏 Intent 与通知

- 渠道重要性 `IMPORTANCE_HIGH`，`setFullScreenIntent(pending, true)`；锁屏页 `showWhenLocked` + `turnScreenOn` + `excludeFromRecents`。
- 通知点按进入 `ReminderActivity`，其「去拍照」带 `MainActivity.EXTRA_ROUTE = "capture"`；主界面用 `initialRoute` 直接落到拍照验证页。
- Android 13+ 需要 `POST_NOTIFICATIONS`：主界面启动时请求一次；我的页也给了重新请求/跳系统设置的入口。

### 3. 漏拍

`markMissed(now)` 把「今天的 PENDING 且 scheduledAt + windowMinutes < now」的待办标为 MISSED。
Receiver 每次响前都会调用；App 打开时也调用，避免用户几天没开、回来看到一堆「待拍」。

### 4. 窗口

`updateWindow(itemId, minutes)`：
1. 更新 `pw_reminder.windowMinutes`；
2. 更新今天该物品所有 PENDING 待办的 `windowMinutes`（已完成的记录不改，保留当时的窗口口径）。
范围 5–180 分钟，UI 给 15/30/60 三档。

## 三、权限与 Manifest

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />
<uses-permission android:name="android.permission.VIBRATE" />
```

- `ReminderActivity`：`exported=false`、`singleTop`、`excludeFromRecents`、`showWhenLocked`、`turnScreenOn`
- `ReminderReceiver` / `BootReceiver`：`exported=false`
- Android 12+ 的 `SCHEDULE_EXACT_ALARM` 需要用户在系统设置里允许；没允许时降级为不精确闹钟（可能晚几分钟）。

## 五、已知限制

- 没接真机：通知、全屏、锁屏、开机重排都只在代码与构建层验证；真机 接上后要逐项实测。
- 国产 ROM（MIUI/HyperOS）默认限制后台与自启动，可能需要用户手动允许「自启动 / 后台弹出界面 / 精确闹钟」，否则通知会晚到或被吞。
- 全屏页目前只显示文案与内置照片，等 M4 接 CameraX 后应改成真实取景。
- 侧载安装时 Android 13+ 的通知权限弹窗只在首次启动出现一次；拒绝后要靠「我的」页去系统设置打开。
