# M4 · 拍照验证闭环

版本：`0.4.0-m4`（versionCode 4）
日期：2026-11-13

## 做了什么

- **CameraX 真拍照**：拍照验证页从「内置照片模拟」换成相机预览 + 快门。
  - `PreviewView` + `ImageCapture(CAPTURE_MODE_MINIMIZE_LATENCY)`，绑定 `LocalLifecycleOwner`。
  - CAMERA 运行时权限；没有权限时显示说明与「允许使用相机」按钮。
  - 快门后按 `ImageInfo.rotationDegrees` 旋转，JPEG 落盘。
- **照片落盘**：复用旧工程 `cv/PhotoStore`，路径
  `filesDir/evidence/yyyy-MM-dd/dose-<occurrenceId>-<HHmmss>.jpg`。
- **本机判定**：`ImageQuality.evaluate(bitmap)` + `PillDetection.detect(context, bitmap)`
  （OpenCV DNN 读 `assets/pill_detector.onnx`，失败自动回退经典 CV）。
  - 抽成纯函数 `cv/LocalVerdictJudge.judge(count, expected, qualityOk, qualityIssue)`：
    数量不符 → 「本机看到 X 颗，和应服的 N 颗对不上。」；
    数量对但画质不过 → 「数量对上了，但照片不够清楚（ISSUE）。」。
- **在线判定继续生效**：开启在线识别时，照片压缩成 JPEG 交给 `OnlineVisionClient.judgePhoto`，
  `pass=true` 才写凭物；关闭时走本机判定。
- **完成卡**：通过后用刚才拍的真实照片显示完成卡（时间、物品名 ×N、「已存入今天的凭物」），
  并注明这次是本机检测判定还是在线模型判定。
- **照片 key 统一成字符串**：`MockEvidenceDay.photoKeys: List<String>`、`MockPhoto.photoKey`；
  文件路径以 `/` 开头，`PhotoImage` 用 `BitmapFactory` 两段式采样读盘，资源名仍走
  `painterResource(drawableFor(key))`。首页今日凭物、物品详情网格、凭物台账、完成卡全部共用。
- **调试入口**：Debug 构建在拍照页显示「调试：用示例照片走一遍」，读内置 `pw_photo_2`，
  长边不足 1280 时放大到 1600 再过质量门（`ImageQuality.MIN_LONG_EDGE = 1280`）。

## 模拟器验证（AVD Medium_Phone_API_37.0，1080×2400）

- CAMERA 权限授予后相机预览可见；真实快门拍到虚拟场景 → 本机检测 0 颗 → 正确拒绝并显示原因。
- 调试示例照片 → 检测 4 颗、画质通过 → 完成卡显示真实落盘照片、`盐酸二甲双胍片 ×4`、时间与「已存入今天的凭物」。
- 通过后返回：凭物台账张数 +1（13 张 / 89% / 6 天 / 1 次漏），当天行展开能看到缩略图；
  首页「今日凭物」显示落盘照片；物品详情网格包含这张文件照片。
- 新建物品（`TestPill`、每次 4 颗、22:00）→ 首页「下一次」正确变成该物品 →
  调试照片数量 4 对 4 → 判定通过 → 完成卡 → 「收下这张完成卡」回到首页。
- 修复：完成卡底部文案被系统手势条压住 → 拍照页与完成卡外层加 `navigationBarsPadding()`。

## 已知限制

- 模拟器相机是虚拟场景，真实药片实拍 21/21 与「误放行 = 0」要等 测试机 接上后验证。
- 相机预览比例按 4:3 裁切；不同机型取景框覆盖范围可能略有差异，真机再调。
- 本机检测耗时与发热尚未在中端真机上测；目标 ≤1.5s 出结果。
- 在线判定依赖用户自备 Key 与网络；失败时不写凭物、显示原因，可重试。
