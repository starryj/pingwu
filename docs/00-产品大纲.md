## 0. 一句话说清

到点提醒你，但「完成」不能只点一下——要拍到那件东西的照片，才算完成。
第一版只做**吃药**（药品），但底层按「物品 → 提醒 → 凭证」来设计，以后能长出钥匙、燃气、宠物、垃圾袋这些场景。

## 1. 为什么重做

- 旧工程 RemindMe（吃药了么，您）M0–M6 已完成：提醒/阻塞/拍照检测闭环跑通，实拍 21/21 全对，193 个单测全过。视觉和交互是「能用」级别，不是「想每天打开」级别。
- 产品重新定义（2026-11-12）：不局限药品，用更广泛的**物品**；提醒不只吃药，而是「不要忘记某件事」，用关键物品的照片来解锁。
- 合规现实：药品类目个人上架基本走不通（互联网药品信息服务备案要求法人主体 + 2 名专业人员；医疗健康类目个人通道在收窄）。所以 v1 **不以上架为目标**，先自用/侧载；v1 全部本地识别，不接在线大模型，也不构成生成式 AI 服务。
- 结论：不是把旧 App 改一改，而是**新建项目**：新视觉、新信息架构、通用数据模型；旧工程只读不动，作为对照和代码来源。

## 2. 产品定位

**凭物提醒（proof-of-object reminder）**：每件怕忘的事，绑一件关键物品；到点提醒；拍到那件物品，才算完成。

- 解决的问题：普通提醒点「完成」零成本，容易糊弄自己；把完成条件和一件物品绑定，拍照留凭证，心里更踏实。
- 诚实的边界：**照片只能证明「物品此刻在画面里」，不能证明「你真的吃了/做了」。** App 不声称证明行为，只提供「物品在场 + 时间」的证据，并在界面上把这句话写清楚。
- 不做：用药建议/剂量推荐、社交、云同步（v1）、在线大模型识别（v1）。

## 3. 第一版范围（只做药品）

- 用户：作者自己（长期服药、每天 1–3 次）；后续可给家人用。
- 场景：建药品（含模板）→ 设提醒 → 到点提醒 → 拍照核对药品和数量 → 通过则生成凭证 → 今日/凭证历史可查。
- 文案层：v1 只说「药品/吃药」，不出现「物品」这种抽象词；代码层用通用的 ITEM 模型。
- v1 成功标准（真机连续 7 天）：
  1. 每次提醒都按时触发（含锁屏/熄屏/正在使用三种状态）；
  2. 正常光线下拍照验证通过率 ≥ 95%；
  3. **误放行 = 0**（药不对/数量不对却通过，绝对不允许）；
  4. 无崩溃、无明显发热耗电；
  5. 主观上愿意每天打开，不觉得麻烦。

## 4. 核心闭环

```
建药品（拍 3 张照片登记模板）
   ↓
设提醒（时间 / 星期 / 每次几片）
   ↓
到点提醒（全屏 / 横幅 / 高优先级通知，逐级降级）
   ↓
拍照 → 质量门 → 本地检测 + 模板比对 + 数量核对
   ↓ 通过                         ↓ 不通过
生成「凭物」+「完成卡」           说明原因，提示重拍
（照片 + 时间 + 药名 + 一句鼓励）
   ↓
今日时间线 / 凭证历史
```

分支沿用旧版状态机：延后（≤3 次，从新时间重算窗口）、本次未服（二次确认）、漏服、窗口结束后第 10 分钟最终提醒（可补拍记为迟到）。

## 5. 信息架构

底部 4 个 tab：

| Tab | 内容 | 说明 |
|---|---|---|
| **今日** | 问候、下一/待验证卡、今日进度、时间线、凭物缩略 | 打开先看「欠不欠一次验证」；欠就直接挡到验证页 |

| **凭物** | 按日/周的照片墙、单条凭物详情、台账统计 | 产品的记忆和成就感都在这里 |
| **我的** | 设置、权限检查、隐私（锁屏脱敏）、主题、关于 | 主题切换放这里 |

流程页（从提醒进入，独立于 tab）：**提醒验证页（全屏阻塞）→ 拍照页 → 结果页**；另有最终提醒、模板注册、权限引导。

## 7. 功能清单

### P0（v1 必须有）

- **药品**：增删改、预设外观图标、模板注册（3 张照片 + 一致性检查）、模板状态
- **提醒**：多时间、重复星期、启用/停用、精确闹钟、全屏/横幅/通知降级、延后 ≤3 次、本次未服、漏服、最终提醒
- **验证**：拍照引导、质量门、检测 + 模板比对、数量核对（保留）、失败原因、通过后存凭物
- **凭物**：今日时间线、按日历史、照片查看、台账统计（按时率/连续/漏拍）、保留/清理策略、CSV 导出
- **完成卡**：每次通过生成一张完成卡（时间 + 事项 + 一句鼓励），可收下、可回看；完成卡不是收据，是纪念物
- **设置**：验证窗口（默认 30 分钟，用户可调 5–120 分钟）、延后间隔/次数、照片保留、锁屏脱敏、主题、权限检查
- **权限引导**：通知、精确闹钟、全屏通知、电池白名单
- **诚实提示**：验证页与结果页固定一句「照片证明它在这儿，不证明已经做了」

### P1（v1.1，可选）

- 通用物品模式（钥匙 / 燃气 / 宠物 / 垃圾袋）
- 在线 VLM 识别（已提前到 M2 落地，见 §9）：用户自备 key、默认关、只上传压缩图；不做上架承诺
- 快捷记录：不设计划，拍照即留凭证
- 家庭共享 / 多档案

### P2（以后）

- 状态变化识别（垃圾袋没了、门锁上了、宠物碗空了）
- iOS / 桌面
- 云备份

## 8. 数据模型（代码层通用，v1 文案仍说药）

```
ITEM          物品（v1 的药品）
  id, name, kind(drug|thing), iconPreset, spec, appearance,
  templateStatus, threshold, note

TEMPLATE      物品模板（验证时靠它认出来）
  id, itemId, version, referenceMode, featureJson, refImagePath, threshold

REMINDER      提醒（一个物品可有多条）
  id, itemId, timesJson, daysOfWeek, countPerDose, windowMinutes,
  enabled, startDate, endDate

OCCURRENCE    一次到点（原来的一次服药）
  id, reminderId, scheduledAt, status(pending|reminding|snoozed|
  verified|missed|skipped), snoozeCount

EVIDENCE      凭证（一张照片 + 机器判定）
  id, occurrenceId, photoPath, capturedAt, detectJson, verdict,
  source(offline|online)

PROFILE       使用者档案（v1 单档案，留扩展位）
```

映射：旧 `DRUG → ITEM(kind=drug)`；旧 `DOSE_GROUP → OCCURRENCE`；旧 `DOSE_ITEM` 并入 `OCCURRENCE` 的应服清单 JSON。
**v1 不自动迁移旧数据**；需要的话 P1 做旧 CSV 导入。

## 9. 识别方案

- **v1（本地，默认）**：YOLOX-Nano 单类检测（3.7MB ONNX、输入 320）+ 每药模板特征 + 数量核对；判定 5 条沿用旧版：全部识别、数量相等、置信度达标、无未知、画质通过；任一不满足不许完成。
- **抽象接口**：`Recognizer`（detect / match / verdict），v1 实现 `LocalPillRecognizer`；以后可以加 `GenericObjectRecognizer`、`OnlineVlmRecognizer`，界面不改。
- **在线（M2 已接入，实验性）**：OpenAI 兼容端点，用户自备 key；默认关闭，开关在「我的 → 在线识别」；开启后，**每次按快门由模型判定这张照片算不算本次完成**：模型返回 `pass / count / confidence / reason`，`pass=true` 才写凭物，否则只显示原因；关闭时保持本机模拟判定。保存前先「测试连接」；界面固定提示「开启后照片会发送到你填写的服务商；Key 只存本机」。
- **M4 已换成真照片**：CameraX 真拍照 → 落盘 → 本机 `ImageQuality` + `PillDetection` 判定（数量 + 画质），通过才写凭物、生成完成卡；在线开启时由模型判定（规则同 §9 在线说明），关闭时走本机判定。真机实拍 21/21 与误放行 0 仍待 真机 验证。
- 性能目标：按下快门到出结果 ≤ 1.5s（中端机）；峰值内存 < 200MB。

## 10. 视觉方向（已选 C「值守」，v0.2）

共同底线：正文 16sp、说明 15sp（比常规大）、按钮 18sp；一屏只有一个主按钮；底部与右侧内容不溢出；状态色语义一致（青绿=已验证、琥珀=待验证/延后、珊瑚/朱红=漏、灰=未到）；系统「减少动态」时动画全关。

| 方向 | 关键词 | 底色 | 性格 | 适合 |
|---|---|---|---|---|
| A 深空 | 凭证感 · 安静 | 深墨蓝 + 星点，米色纸本可一键切换并记住 | 像夜里的一盏小灯，柔和、私密 | 想要「安静陪着」的感觉（备选） |
| B 晨光 | 日常感 · 温柔 | 米白 + 苔绿 + 晨光橙 | 像一天开始那样轻，医疗感最淡 | 想让提醒不像「警报」（备选） |
| **C 值守（已选）** | 秩序感 · 清楚 | 深墨 #0A1014 + 纸白 #E8E4D7 + 值守灯琥珀 #F0B45A，票据版式、等宽数字、印章 | 像夜班值守台，一单一单签清楚 | 喜欢台账、想一眼看清欠没欠 |

三版共同的产品细节：底部 4 tab（今日/物品/凭物/我的）；每次通过生成「完成卡/存根」；验证窗口默认 30 分钟且用户可改；诚实提示固定在验证页与结果页底部。

C v0.2 的两处定稿（2026-11-12 你选定 C 时提的）：

- **物品栏沿用 A 的卡片布局**：`我的物品` 页 = 物品卡（图标/药名/剂量/模板状态/提醒时间）+ 添加物品 + 模板说明 + 提醒卡 + 最近凭物，换成 C 的深墨票据配色。
- **凭物栏点开看照片**：台账每一行可点，原地展开当天的照片（08:03 / 21:01 两张），再点收起；不跳页、不打断。

> M1 按 C 做：深色为默认，浅色皮肤用 C 的纸白底（#E8E4D7）派生；双主题令牌统一管理，4 tab 骨架。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 「物品」概念太抽象，用户不懂 | v1 文案只说药；UI 不出现「物品」抽象词 |

| 个人上架受限 | v1 自用/侧载；不接在线生成式 AI；要上架再评估主体 |
| 不迁旧数据 | 旧 APK 保留可查；需要时 CSV 导入 |
