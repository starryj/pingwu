# M2 · 数据层与在线识别

> 版本：`0.2.0-m2`　｜　构建：`BUILD SUCCESSFUL`　｜　单测：14/14

## 1. 这一轮做了什么

M1 的界面靠 `MockData` 跑；M2 把「物品 / 提醒 / 待办 / 凭物」真正落进 Room，界面改成读数据库，并顺手把用户要的「在线大模型 API 识别」接进来做实验。

三条链路：

1. **读**：Room → Repository → Mapper → `UiState` → 各屏
2. **写**：添加物品 → 写 `pw_item` + `pw_reminder` + 今天的 `pw_occurrence`
3. **验证**：拍照（M2 用内置照片模拟）→ 找今天最早待拍 → 标 VERIFIED（超窗记 isLate）→ 写 `pw_evidence` → 完成卡

## 2. 数据模型

数据库：`pingwu_core.db`（version 1，独立于旧工程，避免抢文件）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `pw_item` | id, name, dose, countPerDose, kind, templateReady, coverPhotoKey, sortOrder, archived | 一件看得见的东西 |
| `pw_reminder` | itemId, timesCsv, windowMinutes, enabled | 每天几点要拍（逗号分隔 HH:mm） |
| `pw_occurrence` | itemId, localDate, timeLabel, scheduledAt, state, verifiedAt, isLate, windowMinutes | 某天某时刻的一次待拍；`itemId+localDate+timeLabel` 唯一 |
| `pw_evidence` | occurrenceId, itemId, photoKey, capturedAt, source | 真正拍下的凭物照片 |

状态：`PENDING / VERIFIED / MISSED / SKIPPED`（v1 只用前三个）。

## 4. 仓库接口（`data/core/PingWuRepository.kt`）

```kotlin
suspend fun ensureSeeded()
suspend fun addItem(name, dose, countPerDose, kindRaw, times,
                    windowMinutes = 30, coverPhotoKey = "pw_photo_1"): Long
suspend fun updateReminder(itemId, times, windowMinutes)
suspend fun verifyNextPending(photoKey, capturedAt = nowMs()): VerifyResult?
suspend fun clearEvidence()
fun buildUiItems(...) / buildEvidenceDays(...) / buildPhotos(...) / buildStats(...)
```

- `verifyNextPending` 只认**今天、PENDING**的最早一条；没有待拍返回 `null`（不重复记账）。
- 超时判定：`capturedAt > scheduledAt + windowMinutes * 60_000` → `isLate=true`，完成卡文案换「补上了。下一次按点来。」
- 统计抽到纯函数 `StatsCalculator.compute()`，方便 JVM 单测。

## 5. 在线大模型识别（实验）

设计原则：**用户自备 Key、默认关、只做辅助、说清楚照片会离开手机。**

- 入口：「我的 → 在线识别 · 实验」
- 预设：OpenAI（gpt-4o-mini）、DashScope（qwen-vl-max）、火山方舟（模型名填推理接入点 ID）、DeepSeek（文本接口，不支持看图）
- 存储：`SharedPreferences("pingwu_ai")`，字段 `enabled / base_url / model / api_key`；Key 只存本机
- 请求：`POST {baseUrl}/chat/completions`，`Authorization: Bearer <key>`，content 数组 = 文字 prompt + `image_url` 的 `data:image/jpeg;base64`
- 返回解析：`choices[0].message.content`，兼容字符串或数组片段
- 两个动作：
  - **测试连接**：`max_tokens=8`，要求模型只回「可以」
  - **试一张**：拍照页把内置照片发过去，max_tokens 220，返回两三句画面描述
- 判定：**开启在线识别时，通过/不通过由模型给出**——模型按严格 JSON 返回 `pass / count / confidence / reason`，只有 `pass=true` 才调用仓库写凭物；`pass=false` 或解析失败都不记账。关闭在线识别时，仍由 M2 的本机模拟判定直接通过。
- 解析：`AiVerdictParser`（纯 Kotlin，不依赖 org.json），兼容裸 JSON 与 ```json 代码块，`reason` 做反转义；单测覆盖 6 种情况
- 错误处理：非 2xx 抛 `HTTP <code>：<body 前 240 字>`；超时 20s 连接 / 90s 读取；界面红字显示失败原因
